# Reproduce the report evidence

The report's current results come from the folder pipeline. Install requirements-report.txt on Python 3.10 to 3.13, then run `make analysis` and `make check`, which use the committed de-identified data. Rebuilding that data also needs the private workbook at data/private/responses.xlsx and an ignored manifest as described in scripts/README.md, then `make data`. The rest of this page reproduces the earlier 54-response snapshot, which the report keeps as a sensitivity analysis.

The analyzed CSV is withheld because optional names and free text may identify people. The owner can obtain it from the form Responses menu using Download responses CSV. Store it in data/raw/responses.csv or another approved private location. Request access from the repository owner; original exports are not distributed through GitHub. The CSV checksum and exact expected headers are included in results/report_statistics.json and config/report_export_headers.json. The report analyzes the 54-response export, not an automatically updating live dataset.

From the repository root, after installing requirements-report.txt:

```sh
python -m unittest discover -s tests -t . -v
python scripts/report_evidence.py --input data/raw/responses.csv --output results/report_statistics.json
python scripts/report_power.py --output results/report_power.json
python scripts/report_figures.py --input data/raw/responses.csv --statistics results/report_statistics.json --output-dir results/figures
python scripts/snapshot_group_analysis.py --input data/raw/responses.csv --output results/snapshot_group_statistics.json
python scripts/group_power.py --output results/group_power.json
python scripts/snapshot_figures.py
make check PYTHON=python
```

The evidence script validates exact headers and maps the duplicated questions by their verified positions. It imports neither names nor optional explanations into its analytic objects and writes only aggregate statistics. It reports the current AI-first analysis, omission of the legacy response, reversal of that response's mapping, and the unfiltered comparison. It excludes only both-check failures under the described rule. It does not infer duplicate people, age eligibility, or pilot status.

Report figures live in results/figures and are generated by scripts/report_figures.py using a local CSV and aggregate statistics. The diagnostic figure reveals only binned differences and sorted quantiles without names or response identifiers. Report counts and estimates are verified by scripts/check_report.py. The report's arithmetic mean quality scores and effect direction are original minus AI; report_statistics.json stores AI minus original as explicitly named fields.

Power assumptions are declared rather than estimated from the observed outcome. report_power.py uses a noncentral t calculation and exact symmetric binomial rejection tails. It includes alpha .05 and .025 scenarios. Small exact-binomial power changes are discrete and may be nonmonotonic in n.

scripts/build_report_docx.py builds the Word copy from report/report.md and its figures using python-docx. Run make report first. The owner section Markdown files and sections.json are authoritative. Document rendering and visual verification are performed with the bundled document runtime; QA images are not repository deliverables.

The quality sections come from the folder pipeline. With the private workbook at data/private/responses.xlsx and an ignored manifest as described in scripts/README.md, run `make data power quality hypotheses regression quality_figures slides` and then `make check`.

Debshree’s group script validates the same export schema, imports the student-background category, applies the same comprehension rule, and publishes only aggregate counts, exact Fisher tests and confidence summaries. Group analyses are retrospective/exploratory. The fixed-seed 99,999-label permutation can be reproduced without names or free-text content. `group_power.py` enumerates Fisher rejection regions under assumed rates, not observed effects. `snapshot_figures.py` creates the report images and presentation_chart_data.json using aggregate results only. See presentation/README.md for the editable slide builder.

## Reviewed design and detection deliverables

The current 26-respondent hypothesis values remain in results/quality/hypothesis_tests.json. `python scripts/detection/check_design_review.py` checks their mapping to the member deck, its intended final slide numbers, and stimulus archive integrity. The article/rewrite/prompt hashes are in study/stimuli/checksums.json; provenance.md distinguishes the administered punctuation from the corrected reference. None of these checks regenerates or changes Kuba's analysis outputs.

Debshree's deck is generated by scripts/detection/build_design_slides.py. Run `make slides` after editing that source. Because this target also rebuilds Kuba's deck, the review task ran the target in a temporary copy containing the committed scripts, aggregate results and template, then copied only design_detection.pptx back. This preserves Kuba's committed deck byte for byte. The updated generator writes consistent unsigned chart-axis IDs for interoperability; the charts remain native with embedded workbooks. All deck values originate in results/quality/.
