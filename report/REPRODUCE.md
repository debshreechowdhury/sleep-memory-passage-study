# Reproduce the report evidence

The analyzed CSV is withheld because optional names and free text may identify people. The owner can obtain it from the form Responses menu using Download responses CSV. Store it in data/raw/responses.csv or another approved private location. Request access from the repository owner; no raw data are distributed through GitHub. The CSV checksum and exact expected headers are included in results/report_statistics.json and config/report_export_headers.json. The report analyzes the 54-response export, not an automatically updating live dataset.

From the repository root, after installing requirements-report.txt:

```sh
python -m unittest discover -s tests -v
python scripts/report_evidence.py --input data/raw/responses.csv --output results/report_statistics.json
python scripts/report_power.py --output results/report_power.json
python scripts/report_figures.py --input data/raw/responses.csv --statistics results/report_statistics.json --output-dir report/figures
python scripts/check_report.py
```

The evidence script validates exact headers and maps the duplicated questions by their verified positions. It imports neither names nor optional explanations into its analytic objects and writes only aggregate statistics. It reports the current AI-first analysis, omission of the legacy response, reversal of that response's mapping, and the unfiltered comparison. It excludes only both-check failures under the described rule. It does not infer duplicate people, age eligibility, or pilot status.

Report figures are generated by scripts/report_figures.py using a local CSV and aggregate statistics. The diagnostic figure reveals only binned differences and sorted quantiles without names or response identifiers. Report counts and estimates are verified by scripts/check_report.py. The report's arithmetic mean quality scores and effect direction are original minus AI; report_statistics.json stores AI minus original as explicitly named fields.

Power assumptions are declared rather than estimated from the observed outcome. report_power.py uses a noncentral t calculation and exact symmetric binomial rejection tails. It includes alpha .05 and .025 scenarios. Small exact-binomial power changes are discrete and may be nonmonotonic in n.

scripts/build_report_docx.py builds the Word copy from report/REPORT.md and its figures using python-docx. The source Markdown is authoritative. Document rendering and visual verification are performed with the bundled document runtime; QA images are not repository deliverables.
