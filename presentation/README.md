## Rebuild

The speaker notes in design_detection.pptx still cite the earlier report and form paths until the deck is rebuilt; the builder has the current ones.

Run the analysis/figure commands in report/REPRODUCE.md first. The slide builder uses the bundled `@oai/artifact-tool` JavaScript package and presentation validation helpers supplied with Codex; it does not use python-pptx. Set RUNTIME_NODE_MODULES, RUNTIME_BIN_DIR, RUNTIME_PYTHON and PRESENTATION_SKILL_DIR to the dependency paths returned by Codex’s workspace-dependencies tool. Link node_modules beside the builder to the bundled Node packages, or run an unchanged copy of the builder from a temporary directory containing that link. Set STUDY_REPO_DIR to this repository when running a copied builder. Then run it with the bundled Node executable. SLIDES_BUILD_DIR can point to a private writable build directory; it defaults to .presentation-build (ignored).

The builder exports drafts, validates structure, geometry, fonts and editable chart data, renders slides, then copies the validated outputs to this directory. Review every rendered slide visually after content changes. The finalizer requires a new output path if a previous build exists; use a fresh SLIDES_BUILD_DIR for each revision. QA images/receipts stay in the private build folder. No raw participant data are needed to rebuild the slides.
